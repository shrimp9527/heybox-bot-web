# 代码审查概要：heybox-bot-web

> 审查日期：2026-08-05　审查范围：后端（app.py / core/ / logger/ / config/）、前端（web/）、文档与数据（docs/ / data/）

## 一、项目架构概要

小黑盒（heybox）AI 机器人的 Web 控制台版，本地工具定位。

- **技术栈**：Flask 3.1（开发服务器，监听 `127.0.0.1:5500`）+ requests + Pillow + tavily-python；纯线程模型，无 asyncio；前端为原生 HTML/CSS/JS 单页，无框架无构建。
- **入口**：`python app.py` → `ensure_dependencies()` 自动装缺失依赖 → 初始化各模块单例 → 后台自检线程 → Flask 启动并自动打开浏览器。
- **模块划分**（均为模块级单例 + `get_xxx()` 访问）：
  - `app.py`（1173 行）：全部约 35 个 HTTP 路由 + Token 鉴权 + 启动逻辑
  - `core/bot_engine.py`：机器人主循环（轮询 @ 消息 → 配额分批 → 20 线程池异步生成回复），含多账号轮转、替身模式、副号失败冷却、配额回滚
  - `core/heybox_api.py` / `heybox_sign.py`：小黑盒 API 封装与 hkey 签名
  - `core/llm_client.py`：OpenAI 兼容协议统一客户端（支持图片、流式、401/404 回退）
  - `core/session_manager.py`、`core/access_control.py`、`core/steam_games.py`、`core/task_tracker.py`、`core/stats.py`
  - `config/config_manager.py`：JSON 配置，原子写 + .bak 回退 + dry_run 预校验
  - `logger/log_manager.py`：2000 条环形缓冲 + 按日文件 + SSE 推送
- **前后端通信**：REST（统一 `api()` 封装，`X-Api-Token` 头 + HttpOnly Cookie 双通道鉴权，Token 每次启动随机生成）+ SSE 日志推送（指数退避重连）+ 多路定时轮询。
- **接口契约**：前端调用的全部端点在后端均存在，响应字段抽查一致，零失配。

## 二、兼容性

### 依赖与环境

- **Python 版本**：文档自相矛盾（README 写 3.10+，启动 bat 写 3.9+）；代码本身兼容 3.9。
- **依赖声明**：`requirements.txt` 5 个包全部锁版本，与 `ensure_dependencies` 一致，无漏声明。
- **跨平台**：核心代码路径、编码处理规范，基本跨平台；但启动脚本仅有 Windows `.bat`。
- **浏览器兼容**：`AbortSignal.timeout` 需 Chrome 103+/Firefox 100+/Safari 16+，更老浏览器整个控制台不可用；Google Fonts CDN 在国内网络下会拖慢首屏。

### 文档与代码不一致（README 明显滞后）

| README 声称 | 实际 |
|---|---|
| 支持黑名单模式 | 仅白名单 / 频率两种 |
| 可配置触发关键词、温度参数 | 触发词硬编码正则，无温度字段 |
| 日志在 `data/log/` | 实际写在 `data/` 根目录 |
| SSE 不推历史日志 | 已反转为连接即推最近 100 条 |
| Python 3.10+ | bat 与代码为 3.9+ |
| 项目结构树 | 缺 task_tracker、heybox_sign、json_store 等，目录名还是旧的 |

CHANGELOG 之后新增的多账号、替身模式、任务面板、API Token 鉴权等功能在文档中完全无记录。

## 三、扩展性

- **容易**：新增 AI 提供商（`AI_PROVIDERS` 加一行，纯配置）；新增触发命令（`bot_engine._process_message` 加一个分支）；新增搜索引擎（`web_search.py` 一处注册）；新增配置项（前后端各有成熟套路，约 10–20 行）。
- **中等偏难**：新增前端视图——单 HTML + 2531 行单 JS 文件、全局函数 + 内联 onclick，无模块边界；四套 LLM 配置区块近乎逐行复制，是最明显的可维护性债。
- **困难**：接入小黑盒之外的平台——`heybox_api` 被各模块直接调用，无适配层。
- 无测试、无 lint、无类型检查，重构缺乏安全网。

## 四、问题清单

### 严重

1. **明文凭证落盘**：各 LLM/搜索/Steam API Key 明文存于 `data/config.json`，小黑盒会话 Cookie 明文存于 `data/session.json`，`.bak` 副本同样含全部密钥。当前 `data/` 中存在**真实可用的密钥**——建议立即轮换并注意该目录的敏感性。`.gitignore` 已排除 data/，无 git 泄漏风险，但打包分享项目即泄露。
2. **配置接口全量回读含密钥**：`GET /api/config` 将含全部密钥的配置明文下发浏览器（有随机 Token 保护 + 仅 localhost，属"本地工具可接受但需知晓"的风险）。

### 中等

3. **SSRF 面**：`/api/llm/models_for`、`/api/llm/test_for` 接受任意 `base_url` 由服务端带 Bearer 头发起请求，无白名单/私网过滤。
4. **启动时全局 pip 安装**：`ensure_dependencies` 往当前 Python 环境装包且硬编码清华镜像，可能污染全局环境。
5. **pip 失败路径可能崩掉启动**：`app.py:1102` 按 UTF-8 解码 pip 输出，中文 Windows 下常为 GBK，`UnicodeDecodeError` 会逃出捕获导致进程退出——恰发生在依赖缺失的最坏场景。
6. **失败消息静默丢失**：消息时间戳基准拉取后即推进，AI 生成/发布失败的消息不再被拉到，无重试入口（`core/bot_engine.py:397`）。
7. **回复线程池与 stop 竞态**：`stop()` 将 `_reply_executor` 置 None，并发启停时 `submit` 抛异常，任务被误判失败（`bot_engine.py:144`）。
8. **长任务阻塞 + 线程堆积**：LLM 超时 300s，回复池最多堆积 20 条长阻塞线程；`stop()` 不等待，孤儿线程可能"停止后仍发出回复"。
9. **前端并行数量保存失败回滚错误**：`saveParallelSilent()`（`web/static/js/main.js:722-731`）失败时无条件翻转复选框，从数量输入触发时 UI 与后端配置脱钩。
10. **副号二维码轮询未检查 `resp.ok`**：后端返回错误时显示"状态：undefined"并终止轮询（`main.js:820-833`，主号版本行为不一致）。
11. **前端 30s 全局超时偏短**：LLM 测试类慢接口易被中止，用户收到误导性"请求失败"。

### 轻微

12. 辅助 LLM 配置的 `api_path` 字段被忽略（硬编码 `/chat/completions`），形同虚设。
13. `steam_games.py` 内 urllib 与 requests 混用；`_local_db_cache` 无锁读写。
14. 并行批处理退出时隐式 `shutdown(wait=True)`，stop 不即时。
15. 日志导出只导内存环形缓冲（2000 条），不含磁盘完整日志。
16. 数字型 `user_id` 时 `_getUidColor` 哈希全为 0，全部同色；`showConfirmModal` 固定 id 在模态嵌套时会绑错；多处 fire-and-forget Promise 无错误处理。
17. 冗余：`LogManager._log_dir` 初值必被覆盖；类级 + 模块级双单例模式冗余；`.bak` 与主文件内容完全相同，徒增泄露面。

## 五、总体结论

工程质量整体不错：原子写 + .bak 回退、随机 Token 鉴权、副号冷却/摘除、配额回滚、系统化的 XSS 防御（`escapeHtml` + 头像 URL 协议白名单）、SSE 重连、接口契约零失配。

优先处理顺序建议：

1. 轮换 `data/` 中已暴露的真实密钥，明确该目录敏感性
2. 修复 pip 自举的解码崩溃路径（中等 5）与全局污染问题（中等 4）
3. 更新 README 使其与实现一致
4. 按需处理失败消息重试、启停竞态、前端回滚 bug
